# Фрагменты исходной CRM: исправление направления

Пользователь уточнил: не создавать новый интерфейс CRM и не показывать целые страницы. Требуются небольшие фрагменты из архива, анимированное заполнение пустой формы и свободный выбор возможностей. Это уточнение заменяет прежнюю последовательность из 10 полноэкранных глав.

## Реализация

- Кнопка «Начать» на первом экране ведёт к форме.
- Два поля из `app/landing.jsx → Register` изначально пустые. Затем последовательно появляются имя, почта, нажатие кнопки и четыре цифры кода. Кнопки неактивны до заполнения.
- Воспроизведение занимает около восьми секунд активного просмотра. Пауза, повтор и переход к возможностям доступны отдельно. В reduced-motion переходы выполняются кнопкой «Продолжить» без печати по буквам.
- После входа открываются 9 карточек выбора. Они дают доступ к 22 небольшим фрагментам: данные, история, заметки, переписка, четыре системы расчётов, встреча/перенос, продукт/редактирование, подготовка/материалы, дневник/ответ, цепочка/AI, публикация/справочник, финансы/профиль.
- Никакого app shell, бокового меню, скриншотов или iframe. Старые `CrmPanels`, `CrmCharts`, `JourneyChapter` удалены.
- Убраны надписи и accessibility labels со словами «демо» и «демонстрационный кабинет».

## Происхождение интерфейса

| Новый файл | Источник из архива | Что перенесено |
|---|---|---|
| AccessFragment.tsx | landing.jsx / Register | Поля, кнопки, блок получения кода; исключены атмосферная колонка, телефон и провайдеры входа |
| SourceIcons.tsx | icons.jsx | Оригинальный SVG-набор; добавлены TypeScript-типы и aria-hidden |
| SourceWheel.tsx | wheel.jsx / NatalWheel | Исходная геометрия, цвета, глифы, аспекты; уникальный id градиента |
| SourceCalculations.tsx | matrix-data/graph, numerology-data/extra, hd-data/graph | Исходные SVG и числовая сетка; убрана оболочка страниц, stores и лишние органы управления |
| SourceFragments.tsx | shared.jsx, crm-card.jsx | Avatar, InfoRow, фрагменты заметок, истории и переписки |
| SourceFragments.tsx | calendar-panels.jsx, products.jsx | Данные одной встречи, слоты и отдельная карточка продукта |
| SourceFragments.tsx | journal.jsx, flow-nodes.jsx, content.jsx, finance.jsx, onboarding-steps.jsx | Запись дневника, три связанных узла, публикация, баланс и поля профиля |
| sourceFragments.css | styles.css + app.jsx / TWEAK_DEFAULTS | Выбранные оригинальные правила в локальном scope; золотой акцент из настроек исходного приложения |

Добавлены только композиция фрагментов на лендинге, анимация входа, выбор функций, локальные данные/действия и адаптивные ограничения. Google Fonts, внешние stores, отправки, платежи и backend исходного приложения не подключались. Onest отсутствует среди локальных файлов архива, поэтому используется уже имеющийся Manrope как fallback; глобальные шрифты не изменены.

## Проверки

- Автоматические: все 22 состояния рендерятся без app globals, iframe/изображений, внешних form actions, NaN/undefined и запрещённых подписей. Тесты подтверждают два пустых поля, порядок печати и кода, работу порога видимости на низком viewport.
- Браузер, desktop: «Начать» → завершение входа → карточки; выбор клиента, сохранение заметки, возврат к функциям, исходная натальная карта.
- Браузер, 390×844: завершение входа, две колонки выбора, заметки, три узла автоматизации, редактирование и подтверждение AI-текста.
- Браузер, 320×740: поля профиля; ширина документа 320px, элементы нового блока не выходят за viewport.
- Reduced motion: пустые поля, отключённая автоматическая печать, ручное продвижение и выбор функций.
- Финальный проход reduced-motion: заполнение → код → вход → выбор функций → возврат через «Начать». Завершённая форма остаётся на месте, повторного автоматического перехода нет. Консоль браузера без ошибок и предупреждений.
- Итоговый запуск `npm test -- --run --exclude 'experiments/**'`: 301 тест в 39 файлах прошёл. `npm run build` и `git diff --check` завершились успешно.
- По code review исправлены: недостижимый порог видимости высокой формы, повторный переход после завершения, повторный focus при смене reduced motion. SVG-фрагменты статичные; числовая сетка использует обычные кнопки.
- Формы и изменения состояния работают только в памяти страницы. Внешних действий не выполнялось.

Первый экран, «Начать», существующий звёздный renderer, коммерческие блоки и финальный тоннель сохранены. Прежнее обрезание CTA защищённой шапки на 320px остаётся вне этой правки. Предупреждение Vite о крупном JS-chunk также сохраняется. Исходный сломанный эксперимент physicalDial не изменён.

Изменения только локальные: без коммитов, push, установки зависимостей и публикации.

## Доведение первого перехода

По снимку пользователя воспроизведена остановка на scrollY=518px: opacity заголовка 0.623, форма ещё за пределами экрана. Причина — ручной scroll управлял всей длиной первого перехода без автоматического завершения.

Добавлен локальный обработчик `openingScrollCompletion.ts`: после 240ms без прокрутки доводит открывающий переход до формы; при движении вверх возвращает к началу. Учитывает удержание пальца/ползунка, скрытие страницы, очистку слушателей и таймера. В режиме reduced-motion не подключается. За пределами первого перехода ничего не доводит; renderer, CSS и длительности фоновых анимаций не менялись.

Проверены в браузере короткий жест вниз до формы и обратный жест до scrollY=0. Автоматические проверки: 307 тестов в 40 файлах, включая 6 новых сценариев перехода; сборка и `git diff --check` прошли. Существующее предупреждение о размере JS-chunk сохраняется.
